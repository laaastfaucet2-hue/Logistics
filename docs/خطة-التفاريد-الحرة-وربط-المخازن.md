## ٢) المراجعة الشاملة على التابين (المخرج: تقرير مكتوب + إصلاحات + اختبارات)

### ٢-أ) منهج المراجعة (٥ محاور)
1. **مطابقة الأرقام**: كل رقم ظاهر (وكل رقم داخل ملف Excel) يُقارن بقاعدة الشهر سجلًا بسجل.
2. **صحة الحساب**: القوة × أيام السريان، الإجماليات، الملحقات، النسب، التقريب (٣ خانات عشرية عربية).
3. **الحدود**: شهر ٢٨/٢٩/٣٠/٣١ يومًا، مدة تعبر نهاية الشهر، يوم بلا سجل، جهة بلا أسماء، أسماء مكررة، أرقام هندية/عربية مختلطة.
4. **الأخطاء البرمجية**: كل مسارات GET/POST (لا 5xx ولا استثناء)، حالات الجلسة المفقودة، ملف مقفول، نسخ شهر، حذف جهة لها ملفات.
5. **الاتساق بين التابات**: الراغبين ↔ التاميدات (نفس القاموس)، التنبيهات ↔ الاثنين.

### ٢-ب) نتيجة الفحص السريع الذي نُفِّذ الآن (قبل الخطة)
- التاميدات: **١١ تأميدة · ٧ جهات** — لقطة JSON = القاعدة تمامًا، والإجماليات (المومدة/أيام التميد/إجمالي القوة) مطابقة.
- الراغبين: **١٤ ملف يوم/جهة** — كل ملف موجود له تسجيل حقيقي، وكل تسجيل له ملف (لا يتيم ولا ناقص).
- الملاحظتان الوحيدتان المقصودتان: ملفا قوة **مستشفى سيناء العام** موجودان بلا أسماء — وهذا مقصود لأن الجهة غير مسجلة في «الجهات والكوادر المعتمدة» ليظهر تنبيهها في جدول التنبيهات.
- **الخلاصة المبدئية:** الأرقام سليمة ومتطابقة. المراجعة التفصيلية (المحور ٢ و٣) ستُنفَّذ بالنص على كل تاب وبتقرير مكتوب في `docs/مراجعة-التاميدات-والراغبين.md` مع قائمة «خطأ ⇒ ملف:سطر ⇒ إصلاح ⇒ اختبار إثبات».

### ٢-ج) المخرج المطلوب تسليمه
| المخرج | الشكل |
|---|---|
| تقرير المراجعة | ملف `docs/مراجعة-التاميدات-والراغبين.md`: جدول أرقام كل تاب + قائمة المشاكل + الإصلاحات |
| اختبارات الإثبات | زيادة `tests/` — كل خطأ يُصلَح ياخد اختبار يمنع رجوعه |
| إصلاحات | تُنفَّذ في نفس الدفعة، وكل إصلاح يظهر في تقرير الأثر |

## ٣) مفتاح الحروف (ض / أ / م)

- **المعنى:** ض = ضابط · أ = أفراد · م = مجندين.
- **النطاق المقترح:** كل مواضع التاميدات والراغبين (جدول التنبيهات · بنر اليوم · نصوص التنبيهات · بطاقات الإحصاء).
- **الشكل:** `ض ١٠ · أ ٢٥ · م ٠` بدل «ضباط ١٠ وأفراد ٢٥ ومجندين ٠»، مع سطر تعريف صغير أسفل الجدول: «ض = ضابط · أ = أفراد · م = مجندين».
- **ملاحظة:** جدول التنبيهات عنده بالفعل رؤوس أعمدة `(ض/أ/م)` و`(ض/أ)` — التغيير سيكون داخل القيم والنصوص.
- **استثناء:** المستندات الرسمية المطبوعة والملفات Excel تبقى بالكلمات الكاملة (ضباط/أفراد/مجندين) لأنها ورق رسمي.

## ٥) آلة حاسبة ٢ مخازن (calc2) — الربط الحقيقي بالمخازن

### ٥-أ) المشكلة الحالية (مؤكدة من الكود)
`templates/calc2/page.html:171-172`: عمودا **«الرصيد المتوفر بالمخازن»** و**«الحالة الكلية للرصيد»** مكتوب فيهما حرفيًا **«قيد التطوير»**.
أما **«التعديل والكمية الفعلية»** فهو حقل إدخال يُحفظ داخل الإذن (`actuals`) ويصل فعلًا للمخازن عبر `db_warehouses.permits_book → tafreeda_rows` (تفريدة FEFO) — لكن **لا يظهر للمستخدم أثرُ التعديل لحظيًا**، ولا يوجد زر «تعديل الإذن» بمعزل عن إعادة الحفظ الكامل.

### ٥-ب) المطلوب تنفيذه
| العمود/العنصر | السلوك الجديد |
|---|---|
| **التعديل والكمية الفعلية** | يظل قابلًا للتحرير، ويُضاف زر **«💾 تحديث الإذن»** لكل صف/إذن: يعيد حفظ الإذن بنفس الرقم (استبدال لا تكرار — `save_permit` يستبدل بنفس الرقم) ⇒ **يتعدل الرصيد في المخزنين + تتعدل التفريدة فورًا** وبدون خصم مزدوج |
| **الرصيد المتوفر بالمخازن** | يُقرأ لحظيًا من المخازن: الكمية بالوحدة الأصلية **+ جنبها الرصيد بالتغليف** (مثال: «١٢٠ كجم — ٢ شكارة + ٢٠ كجم») مع تمييز **الرصيد المنصرف بعد هذا الإذن** |
| **الحالة الكلية للرصيد** | ثلاث حالات ملوّنة: **آمن** (يكفي مع هامش) · **يوشك على النفاذ** (يكفي بالكاد) · **لا يوجد** (صفر) — والحدود قابلة للتعديل من الإعدادات |
| **٢ مخازن تفاريد** (تاب جديد لتخطط له) | تاب مستقل لعرض تفريدة الإذن: الصنف · الدفعة (FEFO) · صلاحيتها · المنصرف مفكك بعبواته · رصيد المخزن قبل/بعد — بنفس بنية التفريدة الحالية `tafreeda_rows` |

### ٥-ج) التنفيذ التقني
- خدمة جديدة `services/stock_link.py`:
  - `availability(year, month, item_name, needed, cycle)` ⇒ `{unit, avail, pack_text, status}`.
  - تعتمد `db_warehouses.item_balances` (رصيد الدورة) + `pack_specs_map` (التغليف) + `stores_report` (توزيع المخازن).
- مسار جديد `GET /calc2/stock` يُرجع الرصيد والحالة لكل صفوف الجدول (يُحدَّث عند تغيير أي رقم).
- مسار `POST /calc2/permit/<number>/update` لتعديل كمية فعلية واحدة ثم إعادة بناء التفريدة + تحديث مرايا المستودعات (`warehouses_fs.snapshot_all`).

## ٦) صفحة «عمل تفاريد حرة» (جديدة كاملة — مطابقة للسكرين شوت)

**المبدأ الملزم:** صفحة **حرة تمامًا وغير مرتبطة بالمخازن ولا بالمقررات** — أي تعديل داخلها **لا يمسّ** مقررات المتعهد ولا التموين ولا أرصدة المخازن، ولها **ملفاتها المستقلة** (المكان: سؤال ٥).

### ٦-أ) الهيكل (٤ تابات رئيسية كما في السكرين شوت)
1. **حسابة الصرف وطباعة الإذن** — بونات ومعاملات دفاتر ٢ مخازن (تلقائي) · تفريدة إدارية منفصلة (تسجيل حر) · تجميع التفريدات للدفتر (يوم بيوم) · اختيار إذن صرف معلق وتفليحه · «البونات النشطة وبانتظار تفريد الصرف» · سجل التفريدات المنجزة والمصروفة.
2. **عمل التفريدة** — الجهة المستلمة · تاريخ · القوة (أفراد) · عدد الأيام ⇒ شبكة الأصناف (المحسوب للغذاء = المعدل × القوة × الأيام) بالوحدة الأصلية وبالوحدة المخزنية، + «توليد كشف التفريدة الإدارية وحماية الصرف» + الأرشيف.
3. **تفريدات الدولي** — من/إلى تاريخ · أمين المخزن · كاتب التعهدات · تصفير وإعادة تعيين القوات · حفظ التفريدة على القرص · السجل · البحث السريع · طباعة كل الأوراق · الكشف الإجمالي العام · النقاط الصفرية.
4. **فتح المجلد** — فتح فولدر ملفات الصفحة (بنفس نمط «فتح مجلد الراغبين» مع بديل تنزيل في نسخة الويب).

### ٦-ب) الأقسام الداخلية (كما في السكرين شوت حرفيًا)
- **القسم الأول:** تفاريد الخطوط — بطاقة الخط (عدد النقاط · إجمالي القوة · النقاط النشطة) + عرض (مجمّع وفردي معًا / مجمّع فقط / نقاط فردية) + شبكة بطاقات النقاط لتسجيل القوة.
- **القسم الثاني:** إدارة الخطوط والنقاط — إضافة خط · إضافة نقطة وربطها بخط · جرد الخطوط (+ حذف/تعديل).
- **القسم الثالث:** تعديل معدلات تفاريد الدولي — اسم الصنف · الوحدة · المعدل اليومي للفرد · تفعيل · أيام الصرف ١..١٠ · إضافة صنف (تمويني/متعهد) · تبويبان للأصناف.
- **معدلات الأصناف** — الصفحة المطلوبة نصًا: **تسحب الأصناف من مقررات المتعهد ومقررات التموينيات** (لقطة عند الفتح) ثم تُعدَّل بحرية، وتوزّع على الأعداد، وتحسب — وتحفظ في ملفاتها المستقلة.

### ٦-ج) المطبوعات (٣ مستندات مطابقة للسكرين شوت)
1. **إذن صرف بون تعيينات مجمع** — أعمدة: م / اسم الصنف والمادة الغذائية / الوحدة / المعدل اليومي / أيام الصرف / إجمالي الحصة المجمعة للخط / ملاحظات + ترويسة القوة والنقاط والفترة + التوقيعان.
2. **بيان توزيع وإجمالي تعيينات خطوط حراسة الدول** — عمود لكل صنف بعنوان «١٠ أيام (وحدة)» + صف الإجمالي العام + التوقيعان.
3. **ورقة النقطة الفردية** — تفريدة نقطة واحدة.

## ٧) تنسيق صفحة المقررات التموينية

**المشكلة (من الكود):** في `templates/rations.html:78-85` حقل «الوحدة» هو الحقل الوحيد الذي تحته سطر شرح (`panel-hint`: «قائمة موحّدة للتموين والمتعهد…») — فيرتفع هذا العمود و**تخرج عناوين «فطار / غداء / عشاء» غير محاذية لخاناتها**.
**الحل المقترح:**
1. شبكة الحقول تصطف على **أعلى الصف** (`align-items: start` + ارتفاع تسمية موحّد).
2. نقل سطر الشرح إلى **أعلى النموذج** (سطر واحد مستقل) أو تحت النموذج بخط صغير — فلا يكسر صف الحقول.
3. توحيد عرض الحقول (اسم الصنف أوسع · الوحدة/فطار/غداء/عشاء بأعمدة متساوية) + محاذاة الأرقام عربيًا.

## ٨) الدفعات المقترحة ومعايير القبول

| الدفعة | المحتوى | القبول |
|---|---|---|
| **١ — الضبط السريع + المراجعة** | مفتاح ض/أ/م · الفوتر · تنسيق المقررات · تقرير المراجعة المكتوب + إصلاح ما يظهر | pytest كامل أخضر + لقطة قبل/بعد + تقرير مكتوب |
| **٢ — ربط المخازن** | الرصيد المتوفر + الحالة الكلية + تحديث الإذن ⇒ المخزنان والتفريدة | اختبار: تعديل كمية ⇒ يتغير رصيد المخزن والتفريدة (وبدون خصم مزدوج) |

| **٤ — أذونات الصرف والمطبوعات** | التابات الأربعة + الـ٣ مطبوعات مطابقة للسكرين شوت | مطابقة بصرية + طباعة سليمة + اختبارات بيانات |

## ٩) المخاطر
1. **حجم العمل كبير** — لذلك التقسيم لدفعات أعلاه، ولا دفعة تُسلَّم بغير اختبارات.
2. **مطابقة التصميم**: أي فرق عن السكرين شوت يبقى قرارًا مكتوبًا لا اجتهادًا.
3. **صفحة التفاريد الحرة لا تمس الواقع**: يجب ألّا تتسرّب أي قراءة/كتابة منها لفولدرات المقررات والمخازن — يمنعها اختبار آلي.
4. **بيانات العرض**: كل التطوير والتجارب في الشهر النشط للعرض فقط (`LOGISTICS_SEED_DEMO=1`)، ولا تمس بيانات المستخدم الحقيقية.
